入耳式耳机功能扩展 · 软件原型

用浏览器 Web Audio 管线实现三大实验能力：通透模式（环境监听）、软件声音处理链路（虚拟声卡测试版）、主动降噪实验（低频反相抵消），另附测试信号发生器用于调试验证。

⚠ 浏览器原型 ≠ 成品：真正的“系统级虚拟声卡”需要虚拟音频驱动 / WASAPI 环回；真正的 ANC 需要毫秒级以内 DSP 与耳内反馈麦克风。本页先验证算法与体验，限制与路线见文末《原理 · 限制 · 路线图》。

输入 A · 环境/耳机麦克风

通透模式与 ANC 实验共用此路环境音输入。建议把耳机（含麦克风）设为系统默认播放+录音设备，且佩戴后再打开相关模块，避免外放啸叫。

输入 B · 系统声音（环回/虚拟声卡位）

浏览器内实现“捕获整机声音”的两种方式：
  • 方式① 点上方按钮，在系统弹窗里选择整个屏幕 / 任意窗口并勾选“分享系统音频/选项卡音频”。
  • 方式② 启用系统“立体声混音”或安装 VB-Cable / VoiceMeeter，然后把它当作“麦克风设备”在下拉里选择（等效全系统虚拟声卡）。

快速上手（Windows 部署与测试）
  1. 打开本文件：推荐 Chrome / Edge 双击打开，或起本地服务后访问（更稳）：python -m http.server 8000 → http://localhost:8000。若嵌在其它面板无法授权麦克风/共享，请改用浏览器直接打开本文件。
  2. 把有线入耳耳机（含麦）设为系统默认播放与录音设备并佩戴。
  3. 点【获取麦克风】→ 点【▶ 启动音频引擎】。
  4. 通透模式：打开“通透模式”开关，从小音量上调到舒适位置（AEC 默认开启可防啸叫）。
  5. 虚拟声卡链路：选“处理输入=系统声音”→ 点【共享系统音频…】→ 在弹窗勾选“分享音频”→ 打开引擎开关 → 播放任意系统声音并调节 EQ。整机级替代：启用 Windows 立体声混音（右键音量→声音设置→更多声音设置→录制→启用并设为默认），或安装 VB-Cable / VoiceMeeter 后，在麦克风下拉选择其输出。
  6. ANC 实验：打开开关后用低频噪声源调试“延迟补偿”，详见卡片内说明。
原理 · 限制（为什么要说清楚）

1) 虚拟声卡：页面里能做到什么

网页无法注册操作系统级音频设备。真正的虚拟声卡 = 一个“虚拟播放设备”，让所有应用默认输出到它，再由程序处理后转发给物理耳机。浏览器只能通过两条近似路线：

  • 屏幕共享回环（本页已实现，需每次授权）；
  • 系统“立体声混音”/ VB-Cable 之类虚拟线材把整机声音呈现为一个麦克风（本页可直接选用，最接近虚拟声卡体验）。

2) ANC：浏览器为何做不出完整版

噪声抵消要求在噪声到达鼓膜前，发出精确反相的声波。关键指标是端到端延迟：

频率波长浏览器链路 ~30ms 造成的相位误差能否抵消
100 Hz3.4 m≈3 个周期内约 11% 相位差可部分抵消（低频嗡嗡声变轻）
1 kHz0.34 m≈30 个周期，相位基本随机不能，可能反而增强

因此本模块把反相信号限制在 300Hz 以下做演示。AirPods 级 ANC 之所以可行，是因为专用 DSP（亚毫秒延迟）+ 耳内反馈麦克风 + 密闭腔体，三者缺一不可——那是硬件方案，不是软件可以替代的。

3) 通透模式：最适合网页实现

麦克风→耳机直通，几十毫秒延迟在人声/环境监听中可接受，配合低切、压缩与 AEC 即得到可用的监听链路。这正是本原型里最“成品化”的一个模块。

v0.2+ 产品路线图建议（脱离浏览器后）
  • v0.2 · Electron 桌面版：Windows 用 WASAPI Loopback 直捕整机声音（免共享弹窗、免虚拟线材），打包成常驻托盘应用，实现真正的“开机即用的软件虚拟声卡 + 全局 EQ”；麦克风侧增加低延迟 ASIO/WASAPI Exclusive 模式。
  • v0.3 · 专用 DSP 硬件（ANC 真正的路）：有线耳机线控盒里集成低延迟降噪 DSP（如支持 ANC 的音频 Codec/DSP 芯片），做前馈+反馈双麦克风闭环；或用带 DSP 的 USB 音频方案（XMOS 类）承载 ANC、通透、EQ 三种模式并支持手机直插。
  • 模式统一入口：通透 / 降噪 / EQ 三种处理在硬件上共享同一条 DSP 管线，用户按场景切换或混合。
免责与安全

本页为实验性软件原型，不构成助听器、听力保护或医疗设备。请始终保持合理音量（建议不超过 85dB 长时间听音），佩戴耳机调试 ANC/通透时从小音量开始，出现不适或啸叫立即停止。麦克风权限与屏幕共享均在本地处理，不上传任何音频数据。
