01 / 原理

不是任意一束低频

抵消需要让反噪声到达耳膜时，与当时的噪声幅度相同、相位相反。延迟、耳塞密封性和耳道形状都会改变结果，甚至使噪声增强。

02 / 硬件

麦克风的位置很重要

真正的 ANC 通常使用耳机外部参考麦克风、耳内误差麦克风和专用低延迟 DSP。电脑或线控麦克风无法直接测量耳膜处的残余噪声。

03 / 下一版

先软件，再硬件

先用桌面音频引擎实现系统路由、EQ 与通透。要实现有效 ANC，需要另行开发带麦克风与 DSP 的耳机或 USB 音频硬件。

快速开始

  1. 连接有线耳机

    在 Windows 声音设置中选它作为输出设备，降低系统音量，再点击「启动引擎」。网页音量不是实际声压级。

  2. 选择一个音乐输入

    优先使用本地文件或测试旋律检查链路。共享音频时，选择其他标签页并勾选「分享标签页音频」。Windows 上的 Chrome / Edge 还可能提供整个屏幕的系统音频共享。

  3. 调节 EQ，混入环境音

    选择预设或拖动 12 段均衡器。打开通透开关并允许麦克风访问，从较低环境音量开始。切换麦克风会重新请求该设备。

共享整个系统的声音可能重新捕获 EarLab 自己的输出而产生回路。建议先共享单个其他标签页；不要共享本页。出现重复声或啸叫时按 Esc 停止全部音频。

声音如何流动

标签页 / 文件 / 测试音→余量 + 6 段 EQ→混音 + 峰值压缩→耳机
环境麦克风→高通 + 低通 + 环境音量↗同一混音输出

音乐输入一次启用一种，通透可叠加。EQ 只调节音乐输入；环境监听有独立滤波与音量。电平显示为数字信号 dBFS，输出延迟为浏览器估计，不包含完整麦克风输入、声学路径与硬件延迟。峰值压缩不等于听力保护。

部署与常见问题

如何在本机测试或部署？

推荐在项目目录运行 python -m http.server 8765 --bind 127.0.0.1，再访问 http://localhost:8765。远程部署使用 HTTPS 静态托管，保留 index.html、styles.css 和 app.js 的同级关系。直接打开 HTML 可尝试本地播放，但采集权限依浏览器而异。

共享后无声，或者听见两份声音？

确认共享对话框勾选音频，且所选来源正在播放。部分系统 / 浏览器不支持系统音频捕获。来源原声可能继续播放，网页无法保证替代原播放路径；需在来源端或系统中正确路由，勿只调低整个系统音量来做处理前后比较。

为什么没有输出设备，或者有蓝牙延迟？

设备名称通常在麦克风授权后才显示。输出切换还需要浏览器支持 AudioContext.setSinkId；不支持时请从系统设置切换。蓝牙协议自身引入额外延迟，开启蓝牙麦克风还可能切换到较低音质模式。

网页关闭后会继续录音吗？

不会。停止引擎、按 Esc 或离开本页会释放所有采集轨道。音频只在本地内存中处理，本项目没有录制、上传或后台服务。普通网页不是全系统常驻音频驱动，后台运行可能被浏览器暂停。
