# EarLab · HTML 耳机扩展原型

本版提供真实的浏览器音频处理链路：音频共享、本地文件、惊喜增强组合、6 段 EQ、麦克风通透、设备选择、数字频谱与一键停止。纯静态文件，无构建依赖、无账号、无上传服务。

## 启动

在本目录执行：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

用桌面 Chrome / Edge 访问 **http://localhost:8765**。本地服务仅监听本机；终端按 Ctrl+C 停止。

- `index.html` + `styles.css` + `app.js`：开发版，三个文件同级部署。
- `EarLab_v0.2.html`：可独立分发的单文件版，运行 `python build.py` 从开发版重新生成。
- 双击单文件可尝试本地播放，但采集功能建议用 localhost 或 HTTPS。远程部署需 HTTPS；局域网 HTTP 地址通常无法取得采集权限。
- 原有 `EarLab_v0.1.html` 保留；推荐以 v0.2 为测试入口。

## 建议测试顺序

1. 将有线耳机设为系统输出，先降低系统音量。启动引擎，点击「试听旋律 · 4 秒」。
2. 选择一首本地音频，点击「播放文件」。先试「日常增强 / 人声清晰 / 游戏定位 / 夜间舒适」，再用低频量感、清晰度和左右平衡做个人校准。
3. 切换原声 / 低音增强 / 人声清晰 / 柔和聆听，或单独调节 6 个频段。EQ 与惊喜增强设置都会在浏览器本地保存。
4. 接入其他标签页的音频，并在共享对话框勾选音频。共享成功后会替换文件或测试音。不同系统和浏览器支持不同，选中窗口不保证提供音轨。
5. 开启通透并授权麦克风。麦克风音量默认 15%，主音量默认 25%；切换输入设备会重启采集。环境音与音乐可同时混合。
5. 按 Esc 或点「停止全部」，验证所有播放停止、共享指示消失、麦克风被释放。单纯静音输出会继续采集；停止全部才释放设备。

麦克风耳返应通过耳机播放，避免外放反馈。音量百分比和 dBFS 不是耳内声压级；峰值压缩不保证不削波，也不构成听力保护。蓝牙通常有额外延迟，开启其麦克风可能降低播放音质。

## 三项需求的实现边界

| 需求 | HTML v0.2 | 后续所需 |
| --- | --- | --- |
| 系统声音经过调节传给耳机 | 通过授权共享音频，做 EQ 后输出；支持浏览器提供的输出设备选择 | 系统常驻路由、虚拟音频驱动、WASAPI 引擎 |
| 真正的虚拟声卡 | 不会注册任何 Windows 音频设备 | 驱动开发或集成已有虚拟音频设备，安装与签名 |
| 类 AirPods 的主动降噪 | 提供数学演示与可开关的低频反相耳返测试，不保证有效降噪 | 参考 / 误差麦克风、声学校准、低延迟 DSP、适合 ANC 的耳机硬件 |
| 有线耳机通透 | 可用：环境麦克风 → 高通 / 低通 → 环境音量 → 耳机 | 更低延迟的桌面音频引擎或耳机 DSP |

主动降噪需要噪声到达耳膜时的准确幅度与相位。任意播放低频，或将远处麦克风信号简单反相，可能增加噪声；不能将这个做法视为已实现 ANC。降噪页使用 `sqrt(1 + a² - 2a*cos(2π*f*delay))` 计算理想单频残余幅度，非实测降噪数值。

## 音频实现

```text
共享音频 / 本地文件 / 测试旋律（一次一种）
  → −6 dB 余量 → 场景增强 + 个性化校准 + 动态 EQ + 6 段 EQ → 混音
环境麦克风 → 高通 40–500 Hz → 低通 9 kHz → 环境音量 → 混音
混音 → 舒适保护 / DynamicsCompressor → 左右平衡 → 主音量 / 静音 → 输出分析器 → 选定输出设备
```

- EQ 的频段为 60、170、500、1000、4000、12000 Hz；每段 ±6 dB。预留增益余量不能保证所有组合都不削波。
- 惊喜增强提供日常增强、人声清晰、游戏定位与夜间舒适四个场景；低频量感、清晰度和左右平衡会叠加到现有处理链。
- 动态 EQ 使用输出频谱做保守修正：低频过重时轻收低频，高频过尖时轻柔高频；它不是机器学习模型。
- 通透不使用自动增益、回声消除或浏览器语音降噪，以免改变环境音；系统 / 驱动仍可能施加自身处理。
- 共享 API 通常要求视频轨道，程序禁用视频轨道并且不读取、存储或上传帧。停止时释放整个共享流。
- 整个屏幕的系统音频捕获可能包含 EarLab 输出而形成回路。优先共享其他单个标签页。`suppressLocalAudioPlayback` 是浏览器提示，不能保证来源原声被抑制；系统级完整替代播放路径需要桌面路由。
- 输出切换使用 `AudioContext.setSinkId`；不支持时使用系统默认设备。设备列表通常需麦克风授权后才能显示名称。返回默认输出时显式使用空设备 ID。
- 延迟数值是浏览器 `baseLatency + outputLatency` 可用项的估计，未包含完整输入 / 声学 / 硬件延迟。页面在后台可能被暂停。
- 本地文件上限 100 MB，格式支持取决于浏览器解码器。音频解码在内存中，不上传文件。

## 验证

```powershell
node --check app.js
python build.py
```

启动本地服务器后打开 **http://localhost:8765/tests/smoke.html**，点击「运行检查」。检查使用真实 Web Audio / OfflineAudioContext，采集接口替换为合成静音流；不请求真实麦克风或屏幕权限。

覆盖 EQ 频响、离线输出与静音、权限拒绝、迟到的权限回调、无音轨共享清理、共享结束、设备切换失败回滚、真实 WAV 解码 / 暂停 / 跨引擎重播、音源互斥、有限时长试听、Esc 释放以及 ANC 数学模型。

自动检查不能确认真实设备音质、系统共享支持、权限对话框行为或耳内延迟；这些需在目标浏览器和耳机上实测。

## 反相耳返试听开关

在「降噪实验室」点击「启用测试」，允许麦克风后开始输出；再次点击「关闭测试」立即断开并释放测试麦克风。权限等待期间也可取消，迟到的授权结果会被丢弃。Esc、停止引擎与离开页面都会关闭测试。

测试链路：所选麦克风 → 40 Hz 高通 → 400 Hz 低通 → −1 反相 → 测试音量（默认 5%，最高 20%）→ 原有混音 / 压缩 / 主音量。与通透互斥，切换不会自动恢复另一模式，音乐继续播放。下方模拟参数不会改变实际音频。

这是反相耳返实验，不是自适应 ANC，不保证减少耳内噪声。请用有线耳机小音量试听，勿外放；可能出现噪声增强或反馈，关闭按钮或 Esc 可停止。
